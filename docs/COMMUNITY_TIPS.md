# 卡友技巧库

更新时间：2026-07-27

## 产品范围

卡友技巧库是审核制的用户经验内容区，不是自由发帖社区。Flutter 主入口位于
“排行榜 → 卡友榜 → 卡友广场”，进入后落到现有“资讯 → 技巧”内容流，不增加新的底部导航。

第一阶段包含：

- 审核后公开的技巧列表与详情；
- 可搜索的关联卡片选择，展示卡面、名称、发行方和摘要信息；
- 一个必填、最多 80 字的技巧标题；
- 一段最多 2000 字的自由经验描述，不要求拆分步骤、适用条件或注意事项；
- 最多三张辅助说明图片，投稿前可预览和删除；
- 公开详情中的封面与正文图片支持点击放大、双指缩放、左右滑动以及上一张/下一张切换；
- 投稿人选择实名昵称或匿名发布；
- 收藏、“有帮助”和纠错入口；
- 投稿后的审核状态、管理员回复与发布结果。

第一阶段不包含评论、私信、用户关注、群聊、收益晒单、开卡成功率投票、付费咨询、邀请码或推广链接。

## 投稿接口

`POST /api/submissions/tips` 只接受已验证账号的 Bearer Token。

无图片时继续使用 `application/json`，请求示例：

```json
{
  "subject": "跨境消费前如何核对完整费用",
  "description": "我在跨境消费前会先把充值、换汇、消费和退款可能产生的费用放在一起核对……",
  "cardId": "card-id",
  "cardName": "示例卡",
  "publishAnonymously": true
}
```

带图片时使用 `multipart/form-data` 提交到同一路径。文字字段名称保持一致，
`publishAnonymously` 使用布尔字符串；每张图片均使用重复的 `images` 字段。

图片限制：

- 最多 3 张，单张不超过 4 MB，总大小不超过 10 MB；
- 仅接受 `image/jpeg`、`image/png` 和 `image/webp`；
- 客户端通过系统照片选择器将长边限制为 1800 像素并进行适度压缩；
- 服务端必须重新校验真实文件类型、尺寸和文件头，生成随机存储名，不信任客户端文件名；
- 原始投稿图片使用私有存储，只有审核人员可以访问；审核通过后应生成去除元数据的公开衍生图；
- 投稿被拒绝、撤回或账号删除后，服务端应按隐私政策删除原图及未使用衍生图。

服务端必须：

- 忽略客户端传入的用户 ID，以 Bearer Token 识别投稿人；
- 默认创建 `received` 状态，不能直接公开；
- 要求 `subject`、`cardId` 和非空 `description`，标题最多 80 字、经验描述最多 2000 字；
- 拒绝邀请码、返佣、Affiliate、CPA、推广内容或隐藏跳转链接；
- 不保存完整卡号、CVV、PIN、证件、密码、验证码或联系方式；
- 对文字和图片执行敏感信息与推广内容审核，疑似包含卡号、证件、二维码或联系方式时拒绝公开；
- 为重复提交、频繁提交和恶意内容设置账号级限流。

## 审核与发布

管理端审核顺序：

1. `received`：投稿已收到。
2. `reviewing`：进行安全、合规和基础事实核验。
3. `accepted`：决定采纳，等待编辑或发布。
4. `resolved`：技巧已经发布，`statusNote` 应说明“技巧已发布”并包含可打开的站内路由。
5. `declined`：无法核验、重复、超出范围或不符合安全规则，并向用户提供简短说明。

审核通过后，由审核人员核对投稿标题，并从自由经验正文中整理摘要和排版；使用现有公开文章体系发布，
不建立第二套内容后台。`GET /api/articles` 的技巧项目使用：

```json
{
  "slug": "community-tip-slug",
  "category": "community-tip",
  "title": "支付前核对完整费用的方法",
  "summary": "适用于跨境消费前核对充值、换汇和支付费用。",
  "rawContent": "## 使用场景\n\n...\n\n## 操作步骤\n\n![步骤示意图](https://card.lengziyu.cn/uploads/tips/public-image.webp)",
  "coverImageUrl": "/uploads/tips/public-cover.webp",
  "tags": ["费用核对", "卡友经验"],
  "relatedCardIds": ["card-id"],
  "author": "匿名卡友",
  "verifiedLabel": "2026-07-26 基础核验",
  "publishedAt": "2026-07-26T08:00:00.000Z",
  "viewCount": 0,
  "likeCount": 0
}
```

匿名投稿发布时只能显示“匿名卡友”，公开接口和文章正文不得泄露账号昵称、邮箱或内部用户 ID。
审核人员可以只采用投稿图片中的一部分；公开图片必须使用去除元数据后的衍生文件，并通过
`rawContent` 的 HTTPS Markdown 图片或 `coverImageUrl` 展示，不得暴露私有原图地址。

## 内容声明

每篇技巧固定展示：

> 本内容来自用户经验投稿，经基础内容审核，不代表发卡方官方说明。费用、地区、KYC 和功能可用性请以官方最新规则为准。

基础审核只代表内容符合展示规则并完成有限核验，不代表 CardFi 或发卡方为用户经验背书。

## 提醒与数据

- 进入 `accepted`、`resolved`、`declined` 或收到管理员回复时，可向投稿账号发送一次定向提醒；
- 相同状态和相同回复必须幂等，不能重复推送；
- “有帮助”只表示内容对用户有参考价值，不计作收益、申请成功率或金融建议评分；
- 第一阶段不公开投稿数量排行榜，不以会员身份改变内容排序；
- 收藏属于用户个人数据，继续沿用现有账号同步和删除规则。

当前 Flutter 已实现卡友榜直达入口、列表、详情、本地回退内容、必填标题、自由正文投稿、可搜索卡面选择、
最多三张图片的选择/预览/删除、multipart 上传和贡献状态衔接。正式开放依赖独立 API、
私有图片存储与管理端完成投稿审核、公开文章分类和定向提醒。

截至 2026-07-27，生产环境 `card.lengziyu.cn` 尚未实现该接口：JSON 请求会返回
`404 Not found`，multipart 请求仍被通用 JSON 解析器处理并返回 `INVALID_JSON`。
开放投稿前必须先部署本节定义的路由和 multipart 解析逻辑。

服务端接入时需要同时完成以下两条路径，不能只加业务路由：

1. `application/json`：在 API 路由中增加 `POST /api/submissions/tips`，校验
   `subject`、`cardId`、`description` 和 `publishAnonymously` 后创建 `tip` 投稿。
2. `multipart/form-data`：必须在通用 `readJsonBody` 之前识别同一路径，使用 multipart
   解析器读取文字字段与最多 3 个重复的 `images` 文件；完成文件校验和私有存储后，再调用同一套
   `tip` 投稿校验与创建逻辑。

两种请求必须返回相同结构的投稿记录，并将业务错误返回为 JSON。仅在通用路由中增加
`tips` 分支无法修复带图提交，因为请求会先在 JSON 解析阶段失败。
