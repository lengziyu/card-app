# Pro 消费账单 AI 分析

更新时间：2026-07-21  
状态：MVP 已进入实现与联调阶段

## 1. 产品目标

为有效 Pro 会员提供消费账单截图分析。用户主动选择一张交易详情截图后，系统提取截图中明确显示的金额、币种、费率和手续费，并用确定性公式计算可核验的实际换算成本与内部差异。

这个功能的价值不是让 AI 猜测“哪张卡更好”，而是把不同 U 卡账单转成统一结构，帮助用户看清：

- 原始消费金额与币种；
- 中间结算金额与币种；
- 最终扣款金额与币种；
- 截图明示的手续费与换汇费；
- 截图明示的多段汇率；
- 实际综合汇率、按截图汇率推导的理论扣款和舍入差异；
- 后续多笔账单和不同卡片之间的可比数据。

## 2. MVP 范围

### 已纳入

1. 仅有效 Pro 账号可以调用分析接口；
2. 从系统相册选择 JPG、PNG 或 WebP 截图；
3. 上传前展示图片，并要求用户确认已排除不必要的敏感信息；
4. AI 仅提取截图中清晰可见的结构化字段；
5. 费率和损耗由服务端固定公式计算，不直接采用模型自行计算的结果；
6. 返回总体置信度和需要用户确认的字段；
7. 客户端展示识别值、内部差异、局限和风险提示；
8. 原始截图不写入账单记录，接口处理完成后不由本服务持久化保存。

### 暂不纳入

- 自动读取相册、邮箱、银行或交易所账户；
- OCR 后自动记账或自动更新用户资产；
- 保存原始账单截图；
- 根据截图推断完整卡号、姓名、订单号、地址或商户身份；
- 在没有可靠市场数据时声称计算“真实市场损耗”；
- 投资建议、收益预测或卡片推荐结论；
- 多账单历史保存、跨设备同步和卡片横向对比。这些作为下一阶段能力。

## 3. 识别字段

服务端要求模型按严格 JSON Schema 返回：

| 类别 | 字段 |
| --- | --- |
| 基本信息 | 平台/厂商、卡片名、交易状态、交易时间 |
| 金额 | 原始消费、结算金额、最终扣款，均包含金额和币种 |
| 费用 | 手续费类型、截图标签、金额和币种 |
| 汇率 | 来源币种、目标币种、1 单位来源币种对应的目标币种数量 |
| 最小识别标记 | 卡号末四位；不提取或返回完整卡号 |
| 质量 | 0–1 置信度、需要人工确认的字段列表 |

字段看不清或截图没有显示时必须返回空值，禁止猜测或用当前市场价格补齐。

## 4. 计算规则

假设原始消费为 `O`，最终扣款为 `D`：

```text
实际综合汇率 = D / O
```

如果截图明确显示一段或多段连续汇率 `R1...Rn`：

```text
截图汇率理论扣款 = O × R1 × ... × Rn
内部舍入差异 = D - 截图汇率理论扣款
```

同币种明示手续费只合计币种与最终扣款币种相同、且截图明确标注的费用。不同币种费用在没有可靠换算链路时不强行相加。

“市场基准损耗”需要交易发生时点的可信外汇/稳定币基准和明确的数据来源。MVP 未接入该基准，因此返回 `not_available`，客户端显示“待接入交易时点基准汇率”。

## 5. 系统架构

```text
Flutter App
  └─ 用户选图、确认隐私、压缩并上传
      └─ 自有 Pro API（鉴权 + 有效权益校验）
          ├─ 调用 OpenAI 图像模型提取严格结构化字段
          ├─ 服务端清洗敏感/异常字段
          └─ 使用确定性公式计算费率和内部差异
              └─ App 展示结果并要求用户核对
```

模型默认使用 `gpt-4o-mini`，通过服务端 `PRO_BILL_AI_MODEL` 可替换。模型只承担视觉识别和字段提取，不承担会员鉴权、金额计算或最终事实判断。

## 6. API 契约

### 请求

`POST /api/pro/bill-analysis`

```http
Authorization: Bearer <short-lived-access-token>
Content-Type: application/json
```

```json
{
  "mimeType": "image/jpeg",
  "imageBase64": "<base64>"
}
```

约束：

- 只接受 JPEG、PNG、WebP；
- 解码后的图片最大 1.35 MB；
- 必须先通过独立账号鉴权和有效 Pro 权益校验；
- 服务端通过文件签名复核图片类型，不只信任客户端声明。

### 响应摘要

```json
{
  "analysis": {
```

## 7. 隐私与安全

- OpenAI API Key 只允许配置在服务端环境变量或部署平台密钥管理中，禁止写入 Flutter、`dart-define`、仓库或客户端日志；
- 上传前明确告知图片会发送到自有服务端和第三方 AI，并取得用户主动确认；
- 不申请整库相册访问，不后台扫描照片；仅处理用户手动选择的单张图片；
- 用户应先裁剪掉姓名、完整卡号、订单号、地址、二维码等不必要信息；
- 服务端和提示词都不返回完整卡号等字段，只允许保留卡号末四位；
- 不记录图片 Base64、访问令牌或完整识别原文；
- 原图不进入账单记录。若未来要保存原图，必须重新进行产品、隐私、存储加密和删除机制评审；
- 上线前在隐私政策中列明处理目的、第三方处理方、数据类型、保留策略和用户删除路径。

## 8. 服务端配置

以下配置全部属于部署环境，不进入 App：

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `OPENAI_API_KEY` | OpenAI 服务端 API Key | 无，缺少时功能不可用 |
| `OPENAI_API_BASE_URL` | OpenAI API 根地址 | `https://api.openai.com/v1` |
| `PRO_BILL_AI_MODEL` | 账单视觉提取模型 | `gpt-4o-mini` |
| `PRO_BILL_AI_TIMEOUT_MS` | 单次模型请求超时 | `30000` |
| `PRO_BILL_IMAGE_MAX_BYTES` | 原图最大字节数 | `1350000` |
| `PRO_BILL_ANALYSIS_RATE_LIMIT_MAX` | 单 IP 每分钟最大分析请求数 | `10` |

## 9. 下一阶段：多账单对比

下一阶段在用户逐笔确认识别结果后，只保存结构化账单数据，并提供：

- 同一卡片按币种、国家/地区和时间区间汇总；
- 不同卡片相同消费币种的综合汇率与明示费用对比；
- 平均损耗、中位数、最大/最小值和样本数；
- 识别结果的手动修正、删除和导出；
- 只有在可靠交易时点基准接入后才展示市场基准损耗。

禁止直接把未经用户确认的 AI 识别结果用于公开排行或评价厂商。

## 10. MVP 验收标准

- 非 Pro、未登录、图片类型错误和图片过大均被服务端拒绝；
- API Key 不出现在客户端产物、网络请求体、日志和 Git 历史中；
- 示例账单可提取 25 CNY、3.73 USD、3.7677 USDT、两段汇率和 0 手续费；
- 示例账单的固定公式结果可由单元测试复现；
- 模型缺字段时页面显示“未识别”而非虚构数据；
- Android 中断选图可尽力恢复，iOS/Android 权限声明与系统选择器行为正确；
- `flutter analyze`、`flutter test` 和服务端测试通过。
