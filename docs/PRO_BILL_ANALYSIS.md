# Pro 消费账单 AI 分析

AI 账单识别面向已登录且已验证账号开放，普通版每个自然月 8 次，Pro 每个自然月 30 次；后台按用户赠送的账单识别额外次数叠加到当月基础额度。历史账单保存等其他 Pro 权益仍按各自入口和服务端规则校验。

更新时间：2026-08-30
状态：识别 MVP 与历史账单客户端已实现；服务端开关仍独立控制可用性

## 1. 产品目标

为已登录并完成验证的会员提供消费账单截图分析。用户主动选择一张交易详情截图后，系统提取截图中明确显示的金额、币种、费率和手续费，并用确定性公式计算可核验的实际换算成本与内部差异。

这个功能的价值不是让 AI 猜测“哪张卡更好”，而是把不同 U 卡账单转成统一结构，帮助用户看清：

- 原始消费金额与币种；
- 中间结算金额与币种；
- 最终扣款金额与币种；
- 截图明示的手续费与换汇费；
- 截图明示且已发生的返现比例或返现金额；
- 截图明示的多段汇率；
- 实际综合汇率、按截图汇率推导的理论扣款和舍入差异；
- 后续多笔账单和不同卡片之间的可比数据。

## 2. MVP 范围

### 已纳入

1. 已登录并完成验证的普通版与 Pro 账号都可以按各自月度额度调用分析接口；
2. 从系统相册选择 JPG、PNG 或 WebP 截图；
3. 上传前展示图片，列明会发送的图片、接收方阿里云百炼 Qwen 和用途，并要求用户主动勾选确认；
4. AI 仅提取截图中清晰可见的结构化字段；
5. 费率和损耗由服务端固定公式计算，不直接采用模型自行计算的结果；
6. 返回总体置信度和需要用户确认的字段；
7. 客户端展示识别值、内部差异、局限和风险提示；
8. 原始截图不写入账单记录，接口处理完成后不由本服务持久化保存。

### 暂不纳入

- 自动读取相册、邮箱、银行或交易所账户；
- OCR 后自动记账或自动更新用户资产；
- 保存原始账单截图；
- 根据截图推断完整卡号、姓名、订单号、地址或商户身份；
- 在没有可靠市场数据时声称计算“真实市场损耗”；
- 投资建议、收益预测或卡片推荐结论；
- 多账单聚合排行、导出和公开卡片横向对比；逐条历史保存已提供独立入口。

## 3. 识别字段

服务端要求模型按严格 JSON Schema 返回：

| 类别 | 字段 |
| --- | --- |
| 基本信息 | 平台/厂商、卡片名、交易状态、交易时间 |
| 金额 | 原始消费、结算金额、最终扣款，均包含金额和币种 |
| 费用 | 手续费类型、截图标签、金额和币种 |
| 汇率 | 来源币种、目标币种、1 单位来源币种对应的目标币种数量 |
| 返现 | 截图明示的返现标签、百分比或已发生返现金额；宣传和预估奖励不提取 |
| 最小识别标记 | 卡号末四位；不提取或返回完整卡号 |
| 质量 | 0–1 置信度、需要人工确认的字段列表 |

字段看不清或截图没有显示时必须返回空值，禁止猜测或用当前市场价格补齐。

## 4. 计算规则

假设原始消费为 `O`，最终扣款为 `D`：

```text
实际综合汇率 = D / O
```

如果截图明确显示一段或多段连续汇率 `R1...Rn`：

```text
截图汇率理论扣款 = O × R1 × ... × Rn
内部舍入差异 = D - 截图汇率理论扣款
```

同币种明示手续费只合计币种与最终扣款币种相同、且截图明确标注的费用。不同币种费用在没有可靠换算链路时不强行相加。

“交易时点市场损耗”需要交易发生时点的可信外汇/稳定币基准和明确的数据来源。服务端尚未接入历史行情，因此该字段仍返回 `not_available`。客户端另外获取最新可用的公开参考汇率用于当前估算：稳定币价格来自现有 CardFi 行情接口，法币参考汇率来自 Frankfurter。该值必须明确显示来源和更新时间，不能表述为交易时点汇率。

客户端展示计算结果时必须遵守：

- `deduction / original` 表示“1 单位原始币种实际扣除多少扣款币种”，不能把币种方向反写；
- 空手续费数组表示“截图未显示手续费”，不能展示为零；只有截图明确识别到同币种的 `0` 金额时才显示零手续费；
- 截图汇率除了需要从原始币种连续连接到扣款币种，还必须与实际扣款汇率处于合理区间；明显冲突的值不得进入计算，并进入待确认项；
- `needsReview` 中包含原始金额、原始币种、最终扣款或扣款币种时，不把相关预览值表述为正式计算结果；
- 识别完成后优先自动采用当前参考汇率估算损耗；获取失败时保留手动输入入口，不回退到疑似错误的截图汇率；
- 结果页优先展示实际综合汇率、损耗、返现和扣除损耗后的实际返现；未经可信汇率校验的理论扣款与舍入差异不进入主结果区；
- 截图没有返现字段时应明确提示用户可以在历史账单中补录返现比例或实际到账金额。
- 积分数量不是返现金额。截图同时显示“获得积分”和括号内现金价值时，必须使用括号内的现金价值作为返现；不得把积分数量套用最终扣款币种。
- 主结果和历史详情分开展示“卡片宣称返现”与“本笔实际返现”；同时展示损耗金额与损耗比例、实际返现金额与按本笔扣款反推的实际比例，以及扣除损耗后的净返现金额与比例。实际返现金额存在时，不得使用另一个识别比例覆盖反推结果。

历史记录默认填入最新可用的当前参考汇率，并允许用户直接修改；同时允许填写返现比例或明确返现金额。返现金额与最终扣款同币种时优先于返现比例，服务端计算：

```text
基准理论扣款 = 原始消费 × 用户提供的基准汇率
毛损耗 = 最终扣款 - 基准理论扣款
返现后净损耗 = 毛损耗 - 返现价值
扣除损耗后实际返现 = 返现价值 - 毛损耗
```

客户端自动填入或用户调整后的基准作为 `calculationInputs.benchmarkRate` 保存，服务端仍按 `user_provided` 处理，不能伪装成交易时点市场行情。截图明示汇率仍保存在 `exchangeRates` 中，和计算基准分开。若当前参考源不可用，字段保持为空并提示用户手动填写。

## 5. 系统架构

```text
Flutter App
  └─ 用户选图、确认隐私、压缩并上传
      └─ 自有 Pro API（鉴权 + 有效权益校验）
          ├─ 调用阿里云百炼 Qwen 视觉模型提取严格结构化字段
          ├─ 服务端清洗敏感/异常字段
          └─ 使用确定性公式计算费率和内部差异
              └─ App 展示结果并要求用户核对
```

模型默认使用 `qwen3-vl-flash`，通过服务端 `PRO_BILL_AI_MODEL` 可替换。模型只承担视觉识别和字段提取，不承担会员鉴权、金额计算或最终事实判断。

## 6. API 契约

### 版本兼容原则

- `POST /api/pro/bill-analysis` 是线上旧 App 使用的 v1 契约，提示词、结构化 Schema 和响应字段保持冻结；新增识别字段不得加入 v1。
- `POST /api/pro/bill-analysis-v2` 是历史账单版本使用的隔离契约，可额外识别返现等新字段。
- `ENABLE_BILL_HISTORY=false` 时 App 调用 v1；启用历史账单的新版构建调用 v2。
- 服务端可先发布 v2 路由；它不会改变 v1 路由，也不会要求线上 App 同步发布。

### 请求

`POST /api/pro/bill-analysis`

```http
Authorization: Bearer <short-lived-access-token>
Content-Type: application/json
```

```json
{
  "mimeType": "image/jpeg",
  "imageBase64": "<base64>",
  "aiDataConsent": {
    "granted": true,
    "version": "2026-08-18",
    "provider": "alibaba-cloud-bailian"
  }
}
```

约束：

- 只接受 JPEG、PNG、WebP；
- 解码后的图片最大 1.35 MB；
- 必须先通过独立账号鉴权，并由服务端按普通版或 Pro 权益读取对应基础额度与当月赠送次数；
- 必须携带与当前版本、阿里云百炼供应商标识匹配的当次主动同意；迁移期间服务端继续接受已发布旧版的 `openai` 标识，避免线上功能中断；
- 服务端通过文件签名复核图片类型，不只信任客户端声明。

## 7. 隐私与安全

- 阿里云百炼 API Key 只允许配置在服务端环境变量或部署平台密钥管理中，禁止写入 Flutter、`dart-define`、仓库或客户端日志；
- 上传前明确告知所选截图会经自有服务端发送给阿里云百炼 Qwen、用于一次性账单字段提取，并取得用户主动确认；
- 阿里云百炼依其服务条款和法律要求处理调用数据；App 内说明与公开隐私政策必须保持一致；
- 不申请整库相册访问，不后台扫描照片；仅处理用户手动选择的单张图片；
- 用户应先裁剪掉姓名、完整卡号、订单号、地址、二维码等不必要信息；
- 服务端和提示词都不返回完整卡号等字段，只允许保留卡号末四位；
- 不记录图片 Base64、访问令牌或完整识别原文；
- 原图不进入账单记录。若未来要保存原图，必须重新进行产品、隐私、存储加密和删除机制评审；
- 上线前在隐私政策中列明处理目的、第三方处理方、数据类型、保留策略和用户删除路径。

## 8. 服务端配置

以下配置全部属于部署环境，不进入 App：

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `BAILIAN_API_KEY` | 阿里云百炼服务端 API Key | 无，缺少时功能不可用 |
| `BAILIAN_BASE_URL` | 百炼 OpenAI 兼容接口根地址 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `PRO_BILL_AI_MODEL` | 账单视觉提取模型 | `qwen3-vl-flash` |
| `PRO_BILL_AI_TIMEOUT_MS` | 单次模型请求超时 | `30000` |
| `PRO_BILL_IMAGE_MAX_BYTES` | 原图最大字节数 | `1350000` |
| `PRO_BILL_ANALYSIS_RATE_LIMIT_MAX` | 单 IP 每分钟最大分析请求数 | `10` |
| `PRO_BILL_HISTORY_ENABLED` | 历史账单服务端灰度开关 | `false` |
| `PRO_BILL_HISTORY_MAX_RECORDS` | 单账号最多保留的结构化记录数 | `500` |

## 9. 灰度阶段：历史账单

识别成功后可保存为“待确认”记录。记录使用独立的逐条存储与版本号，不复用 Pro 工作区的整份快照。每条记录包含不可变的识别值和可修改的用户确认值；卡片关联允许绑定、换绑或保持为空。用户可以逐条修改、解绑和删除，删除账号会同步删除全部历史账单。

App 与服务端必须同时开启功能开关才可用：

- App：`ENABLE_BILL_HISTORY=true`；
- 服务端：`PRO_BILL_HISTORY_ENABLED=true`。

客户端新构建默认展示历史账单入口；发布配置仍可显式关闭。任一开关关闭时，历史账单不可用。历史账单接口为 `GET/POST /api/pro/bill-records` 与 `PATCH/DELETE /api/pro/bill-records/:id`，服务端从短期访问令牌确定用户，不接受客户端传入用户 ID，并使用 `revision` 防止跨设备静默覆盖。

历史列表直接展示卡片、扣款、实际汇率、损耗和实际返现摘要；点击记录进入独立详情页。详情页可生成只包含结构化账单信息的分享图，展示关联卡面、金额、费率、当前参考汇率、损耗、返现和手续费，并由用户主动保存到系统相册；原始截图不进入分享图或历史记录。

后续多账单对比再提供：

- 同一卡片按币种、国家/地区和时间区间汇总；
- 不同卡片相同消费币种的综合汇率与明示费用对比；
- 平均损耗、中位数、最大/最小值和样本数；
- 识别结果的手动修正、删除和导出；
- 当前参考汇率只用于即时估算；只有在可靠历史行情接入后才展示“交易时点市场损耗”。

禁止直接把未经用户确认的 AI 识别结果用于公开排行或评价厂商。

## 10. 灰度阶段：小票打印结果

识别结果支持 Flutter 原生“小票打印”揭晓效果，但默认保持
`ENABLE_BILL_RECEIPT_PRINTER=false`，因此部署代码不会改变当前线上版本。开启后：

- 请求未返回时只显示真实的“Qwen 正在识别账单”状态，不用固定动画伪造 AI 进度；
- 服务端成功返回后才播放约 1.75 秒的阶梯式进纸动画；
- 小票只展示平台、卡片、交易时间、金额、有限条手续费/汇率、综合汇率、舍入差异、置信度和待确认字段；
- 完整费率解释、市场基准状态、免责声明和历史保存状态继续使用现有原生结果卡；
- 打开系统“减少动态效果”时直接显示完整小票；窄屏和大字体不得横向溢出；
- 组件只使用项目自己的颜色、绘制、纸张纹理与锯齿路径，不复制参考网站代码或资源，也不使用 WebView。

## 11. MVP 验收标准

- 非 Pro、未登录、图片类型错误和图片过大均被服务端拒绝；
- API Key 不出现在客户端产物、网络请求体、日志和 Git 历史中；
- 示例账单可提取 25 CNY、3.73 USD、3.7677 USDT、两段汇率和 0 手续费；
- 示例账单的固定公式结果可由单元测试复现；
- 模型缺字段时页面显示“未识别”而非虚构数据；
- Android 中断选图可尽力恢复，iOS/Android 权限声明与系统选择器行为正确；
- `flutter analyze`、`flutter test` 和服务端测试通过。
