# 卡片评论与点赞

状态：已实现；商店版只有在发布前审核开启时才允许提交评论。

## 产品范围

- 只在单张卡片详情展示，不进入首页、全局账户和主导航。
- 详情页预览最多两条评论；“查看全部”进入独立评论页。
- 支持最新/最有帮助排序、幂等点赞、举报后立即隐藏、作者删除、屏蔽作者和游标分页。
- 评论最多 500 字。商店客户端要求全局“开启评论审核”为开启状态：开启时新评论进入 `pending`，审核前仅作者可见；关闭时商店客户端隐藏发布入口，但仍允许浏览、举报和屏蔽。
- 评论禁止外链、邀请码、推广、联系方式和疑似卡号。
- 账号每小时最多发布 5 条、每天最多 20 条。

## 数据与接口

评论、点赞和举报使用 Supabase Postgres 表：

- `card_comments`
- `card_comment_likes`
- `card_comment_reports`

Flutter 不直接访问这些表。请求先到 CardFi API，API 校验账号、功能开关、内容和频率后，才通过服务端密钥访问数据库。数据库已启用 RLS，并撤销 `anon` 与 `authenticated` 的表权限。

公开接口只返回昵称、头像、可选的不可逆匿名屏蔽键和评论展示字段，不返回内部账号标识。当前服务端尚未返回匿名屏蔽键时，客户端使用公开昵称与头像生成本地不可逆摘要作为兼容兜底。屏蔽列表只保存在设备本地，可以在评论安全中心取消；删除账号时会一并删除服务端评论、点赞和举报数据。

## 上线步骤

1. 使用后台仓库的安全脚本预览并执行 `supabase/migrations/20260902011925_create_card_community.sql`。
2. 确认 API 部署环境已配置 `SUPABASE_URL` 与仅服务端可用的 `SUPABASE_SERVICE_ROLE_KEY`。
3. 在管理后台“展示设置”中先只开放测试平台的“显示评论区”。
4. 验证只读列表、后台管理、删除账号和举报处理。
5. 先打开全局“开启评论审核”，验证新评论进入 `pending`，再打开“开放评论互动”。iOS、Android、H5 可分别灰度；商店端不得在关闭审核时开放发布。
6. 正式构建脚本会读取目标平台的线上评论配置；如评论互动已开启但审核未开启，预检会失败并阻止打包。

所有开关默认关闭。未完成数据库迁移或关闭开关时，旧版卡片详情保持原样，不发起评论写入。

### 安全迁移脚本

在后台仓库运行。首次指定 Supabase 项目 REF 后，脚本会检查目标和待执行内容，然后更新数据库：

```bash
npm run db:card-comments -- --project-ref <SUPABASE_PROJECT_REF>
```

项目连接信息会保存在本地，以后更新直接运行：

```bash
npm run db:card-comments
```

如果只想预览而不更新，增加 `--dry-run`。脚本会先检查线上 API 健康状态，要求 iOS、Android、H5 评论展示及评论互动开关全部关闭，并通过 Supabase 的 dry-run 确认只有本次评论迁移待执行。执行前还会要求再次输入项目 REF；非交互环境需要额外传入 `--confirm-project-ref <SUPABASE_PROJECT_REF>`。迁移不会更新 Vault，也不会自动开放评论功能，可以安全重复运行。

迁移已在本地 PostgreSQL 17 隔离容器中验证：点赞与未处理举报计数触发器可正确增减，RLS 已开启，`anon`/`authenticated` 无表访问权限，`service_role` 保留所需的服务端权限。

## 运营规则

- 后台路径：`/admin/comments`。
- “开启评论审核”是商店发布前必开项，只影响保存后的新评论；切换开关不会批量改变已有评论状态。
- 待审核内容可以发布、隐藏或拒绝，并可填写内部审核说明。
- 未处理举报多的内容排在审核列表前面；后台可查看举报原因并选择“有效并隐藏”或“忽略”。前者会先下架评论再关闭举报，处理后未处理计数会自动减少。运营应优先处理隐私泄露、诈骗、推广和骚扰。
- 不建议自动发布。第一阶段观察审核量和举报率后，再决定是否增加自动规则。
