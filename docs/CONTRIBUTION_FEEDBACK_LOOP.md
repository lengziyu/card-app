# 贡献与反馈闭环

更新时间：2026-07-26

## 目标

让已验证用户提交卡片纠错、卡片推荐或留言后，可以持续看到处理状态、处理说明和管理员回复。这个功能用于建立真实的参与反馈，不以签到、积分或无效红点制造活跃。

卡友技巧投稿也复用本闭环；结构化字段、审核发布与内容安全要求见
[`COMMUNITY_TIPS.md`](COMMUNITY_TIPS.md)。

## 客户端状态

Flutter 已支持以下状态，并兼容旧接口缺少状态字段的记录：

| 状态 | API 值 | 用户侧含义 |
| --- | --- | --- |
| 已收到 | `received` | 已进入处理队列 |
| 审核中 | `reviewing` | 正在核对资料与可执行性 |
| 已采纳 | `accepted` | 建议已采纳，等待完成资料更新 |
| 已更新 | `resolved` | 反馈对应的处理已经完成 |
| 暂未采纳 | `declined` | 本次没有采纳，应同时提供简短说明 |

旧值 `pending`、`submitted`、`in_review`、`processing`、`adopted`、`approved`、`completed`、`done`、`updated`、`published`、`rejected` 和 `closed` 会在客户端映射到上述状态。

“消息与反馈”中的“贡献”标签会展示：

- 已提交、处理中和已采纳数量；
- 单条记录的处理时间线；
- 当前状态说明和最后更新时间；
- 管理员回复及回复时间；
- 用户原始提交内容和提交时间。

下拉刷新会同时刷新内容消息与账号反馈记录。

## 反馈查询接口

`GET /api/user/submissions` 继续使用安全账号 Bearer Token。建议响应：

```json
{
  "items": [
    {
      "id": "submission-id",
      "category": "correction",
      "description": "卡片费用已经变化",
      "cardId": "card-id",
      "cardName": "示例卡",
      "createdAt": "2026-07-26T08:00:00.000Z",
      "updatedAt": "2026-07-26T10:30:00.000Z",
      "status": "reviewing",
      "statusNote": "正在核对发行方官方费用页面",
      "adminReply": "感谢反馈，资料团队正在复核。",
      "repliedAt": "2026-07-26T10:30:00.000Z"
    }
  ]
}
```

字段约束：

- `statusNote` 和 `adminReply` 不得包含用户邮箱、访问令牌、后台备注或其他内部信息；
- `updatedAt` 在状态、说明或回复变化时更新；
- `adminReply` 只保存允许用户查看的正式回复；
- 接口必须按当前账号隔离记录，不能接受客户端传入用户 ID；
- 服务端应限制单页数量和文本长度，客户端本地缓存最多保留 100 条。

## 管理端处理规则

管理员处理一条提交时应遵循：

1. 新提交默认为 `received`。
2. 开始核查时改为 `reviewing`，必要时填写简短进度说明。
3. 确认采用但资料尚未发布时改为 `accepted`。
4. 对应卡片资料完成更新后改为 `resolved`。
5. 无法核实、重复提交或不符合收录范围时改为 `declined`，并填写不包含内部信息的原因。

管理员修改状态或回复后，服务端应保留更新时间。不得删除或覆盖用户的原始提交内容。

## 提醒边界

后续可对 `accepted`、`resolved`、`declined` 或新增管理员回复发送一次账号定向提醒，但必须满足：

- 只发送给提交该记录的账号；
- 相同状态或相同回复不得重复发送；
- 通知正文不包含用户提交的敏感内容；
- 用户关闭通知后，状态仍可在 App 内查看；
- 发送记录应可审计。

当前 Flutter 已能显示刷新后的状态和回复；账号定向推送、管理端状态操作及服务端幂等通知仍需在独立 API 与管理端实现。
